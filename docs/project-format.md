# Project Format

Each scan project is stored under the configured local data directory. The backend owns writes to project folders.

```text
project-root/
  metadata/
    project.json
    video_import.json
    frame_extraction.json
    debug_frame_cloud.json
    reconstruction.json
    splat_reconstruction.json
    geometry_bundle.json
    reconstruction_spike.json
    learned/
      depth/confidence/mask/pointmap sidecars
    exports/
      <export-id>.json
    jobs/
      <job-id>.json
      <job-id>.log
  input/
    source videos
  frames/
    frame_000001.png
    frame_000002.png
  reconstruction/
    metadata.json
    cameras.json
    debug-frame-room.ply
    sparse-point-cloud.ply
    learned-point-cloud.ply
    splat.ply
    pointcloud.ply
    scene.glb
  exports/
    result.ply
    result.glb
```

## Artifact labels

- `debug-frame-room.ply` is labeled `debug_frame_cloud_ply`. It is deterministic debug frame planes sampled from flat extracted frames and must not be labeled as reconstruction.
- `sparse-point-cloud.ply` is labeled `point_cloud_ply`. It is a real sparse COLMAP point-cloud reconstruction when produced by `reconstruct_point_cloud`.
- `pointcloud.ply` is a conventional point cloud if produced by another selected pipeline.
- PLY files declared by `metadata/geometry_bundle.json` can be labeled `predicted_point_cloud_ply`. These are learned/predicted geometry outputs and must not be labeled as Gaussian splats, COLMAP sparse point clouds, or verified metric scans.
- `splat.ply` is Gaussian splat data and must not be labeled as a conventional point cloud.
- `scene.glb` / `result.glb` are portable scene exports when a conversion path exists.
- `metadata/geometry_bundle.json` is labeled `learned_geometry_bundle` only when it validates as complete. It describes learned geometry artifacts and sidecars; it is not itself a 3D artifact.
- `metadata/reconstruction_spike.json` is a debug report and must not be labeled as a reconstructed 3D artifact.

## Artifact API

- `GET /projects/{project_id}/artifacts` lists discovered artifacts from `reconstruction/`, `exports/`, and the reconstruction spike debug report.
- `GET /projects/{project_id}/artifacts/{artifact_id}/download` serves a listed artifact.
- `GET /projects/{project_id}/debug-frame-cloud` returns `metadata/debug_frame_cloud.json` when a Frame Room Cloud has been generated.
- `GET /projects/{project_id}/reconstruction` returns `metadata/reconstruction.json` when real point-cloud reconstruction has generated metadata.
- `GET /projects/{project_id}/splat-reconstruction` returns `metadata/splat_reconstruction.json` after a splat readiness/training job.
- `GET /projects/{project_id}/geometry-bundle` returns `metadata/geometry_bundle.json` after it validates as a complete learned geometry bundle.
- Artifact IDs are encoded relative paths generated by the backend; clients should not construct them manually.

## Frame Room Cloud metadata

`metadata/debug_frame_cloud.json` includes:

- `artifact_type: debug_frame_cloud_ply`
- `mode: debug`
- `not_reconstruction: true`
- `params.max_points`
- `params.frame_step`
- `params.arc_degrees`
- `params.plane_width`
- `source_frame_count`
- `frame_count`
- `sampled_points`
- `frame_planes[]` with frame index, source frame, plane position, plane angle, point count, image size, and plane size.

## Sparse reconstruction metadata

`metadata/reconstruction.json` includes:

- `artifact_type: point_cloud_ply`
- `mode: reconstruction`
- `reconstruction_type: sparse_point_cloud`
- `is_reconstruction: true`
- `not_reconstruction: false`
- `debug: false`
- `placeholder: false`
- `adapter: colmap`
- `input_frame_count`
- `registered_frame_count`
- `sparse_point_count`
- `ply_point_count`
- `quality.status`
- `cameras[]` parsed from COLMAP `cameras.txt`
- `registered_images[]` parsed from COLMAP `images.txt`, including `qvec`, `tvec`, and camera center
- `camera_path[]` with ordered camera positions for viewer trajectory rendering
- `trajectory_bounds`
- `params.preset`
- `params.matcher`
- `params.use_gpu`
- `params.recommended_frame_stride`
- `params.recommended_max_frames`
- `colmap.workspace`
- `output_path: reconstruction/sparse-point-cloud.ply`

## Splat reconstruction metadata

`metadata/splat_reconstruction.json` includes:

- `artifact_type: splat_ply`
- `mode: reconstruction`
- `reconstruction_type: gaussian_splat`
- `adapter: nerfstudio-splatfacto`
- `status: blocked_missing_dependencies | succeeded | failed`
- `is_reconstruction`
- `not_reconstruction`
- `input_frame_count`
- `source_frame_count`
- `params.method`
- `params.max_iterations`
- `readiness.dependencies[]`
- `readiness.blockers[]`
- `readiness.next_steps[]`
- `commands.process_data`
- `commands.train`
- `commands.export`
- `output_path: reconstruction/splat.ply` only when a real splat artifact was written.

When Nerfstudio is missing, the job writes metadata with `status: blocked_missing_dependencies`, `is_reconstruction: false`, and `output_path: null`. It must not create a placeholder `splat.ply`.

## Learned geometry bundle metadata

`metadata/geometry_bundle.json` is the adapter-neutral contract for future LingBot-Map/VGGT-style feed-forward adapters. The bundle is valid only when every declared required file resolves inside the project and exists.

Required/high-value fields:

- `schema_version: roomsplat.geometry_bundle.v1`
- `artifact_type: learned_geometry_bundle`
- `mode: learned_geometry`
- `source_adapter`
- `adapter_family`
- `status`
- `complete`
- `is_reconstruction`
- `not_reconstruction`
- `frame_count`
- `frame_index_map[]` with bundle frame index, source frame index, and source frame path
- `cameras[]` with frame index, position, and optional `qvec` or transform
- `intrinsics[]`
- `trajectory[]`
- `capabilities.depth/confidence/mask/pointmap`
- `primary_artifacts[]`
- `sidecars[]`
- `quality`
- `warnings[]`
- `generated_data_rules`

Validation rules:

- `frame_index_map.length` must match `frame_count`.
- `complete: true` requires `status: complete` and at least one primary artifact.
- Incomplete bundles are rejected by the metadata endpoint and do not promote their declared primary PLYs into the artifact list.
- Every source frame, primary artifact, and required sidecar must resolve inside the project folder.
- `predicted_point_cloud_ply` primary artifacts must use `.ply`.
- `mesh_glb` primary artifacts must use `.glb`.
- Learned geometry must set `is_reconstruction: false` and `not_reconstruction: true` until a later adapter explicitly promotes or converts it into another verified artifact type.

Artifact listing sorts real `reconstruction/splat.ply` first when present, then sparse point-cloud reconstruction, learned/predicted point clouds, other point clouds/GLB, debug frame planes, learned geometry bundle metadata, debug reports, and placeholder exports. Placeholder exports remain downloadable, but should appear visually lower priority than real outputs.

## Export API

- `POST /projects/{project_id}/exports` creates a user-facing export from a listed artifact.
- `GET /projects/{project_id}/exports` lists export metadata from `metadata/exports/`.
- Real exports copy an existing `.ply` or `.glb` artifact into `exports/`.
- Placeholder exports can only be created from `metadata/reconstruction_spike.json` when `allow_placeholder` is true.
- Export metadata records source artifact ID, source path, export path, format, artifact label, generated time, `real`/`placeholder` status, warning, and download URL.

## Storage rules

- Keep generated videos, frames, models, splats, checkpoints, and exports out of Git.
- Project folders are created under the configured data directory and named by project ID.
- Project metadata records source video and frame extraction settings.
- `reconstruction_spike.json` records adapter readiness and selected interim reconstruction path when the spike is run.
- `debug_frame_cloud.json` records Frame Room Cloud metadata, including `mode: debug` and `not_reconstruction: true`.
- `reconstruction.json` records real sparse point-cloud reconstruction metadata, including `mode: reconstruction` and `is_reconstruction: true`.
- `splat_reconstruction.json` records Nerfstudio/Splatfacto readiness or successful splat output. Missing dependencies are diagnostic metadata, not a generated reconstruction artifact.
- `geometry_bundle.json` records learned/predicted geometry output contracts. It must validate complete before its primary artifacts are labeled as learned geometry outputs.
- Job metadata records queued/running/succeeded/failed status, params, result, error, timestamps, and log path.
- All paths must stay inside the configured data directory.
- Artifact listing and downloads must resolve paths inside the project folder; escaped symlinks are not valid artifacts.
